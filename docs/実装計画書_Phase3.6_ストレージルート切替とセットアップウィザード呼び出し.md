## **2. 要件**

### **2.1 前提となる意思決定（確定済み）**

| # | 項目 | 決定内容 |
| :--- | :---- | :---- |
| D-1 | 進行中操作がある場合の扱い | **確認ダイアログで警告し、ユーザーがキャンセルした場合は何も変更せず処理を中断する。** 同期・フォルダ再取得・添付/エクスポートのいずれかが進行中のときに切替・新規セットアップが要求された場合が対象。強制的な操作無効化は行わない |
| D-2 | 切替・新規セットアップ完了後の画面遷移 | **アプリを再起動せず、同一プロセス内で新しい `MainWindow` に差し替える。** 旧 `MainWindow` はワーカー停止・`StorageSession` 解放後に破棄し、新しい `AppContext` で生成した `MainWindow` を表示する |
| D-3 | セッションの解放順序 | 設計不変条件を守り、**新セッション開始前に旧セッションを完全に解放する**（ワーカー停止 → `StorageSession.__exit__` によるロック解除・DB接続クローズ）。旧セッションと新セッションが同時に存在する状態を作らない |
| D-4 | 切替先ルートの検証 | フォルダ選択後、`probe()` で検証し **`RootProbe.OK` のときのみ許可**する。`FOREIGN` はエラー表示して拒否、`MISSING` は「新規セットアップウィザードを起動しますか？」と案内する |
| D-5 | 起動時ブートストラップとの共通化 | `run_gui()` 内のルート解決 → `StorageSession` 開始 → `AppContext` 生成 → `MainWindow` 生成のロジックを、起動時と実行中切替の両方から呼べる**共通関数**として `app.py` に切り出す。ロジックの二重実装を避ける |
| D-6 | 設定への永続化 | 切替・新規セットアップ完了後、`config.AppConfig` の `storage_root_candidates` / `storage_root_uuid` / `storage_profiles` を新ルートの内容で保存する（既存の `_commit_setup_root` / `context.save_settings` の仕組みを再利用する） |

### **2.2 機能要件**

- メイン画面のメニューバーに「ストレージ」メニューを追加し、以下の3アクションを配置する。
  - **現在のストレージルートを表示**：`context.storage_root`（絶対パス）・`context.root_uuid`・容量レベル（`context.capability_level`）・暗号化申告（`context.encryption_declaration`）を読み取り専用ダイアログで表示する。
  - **ストレージルートを切り替え...**：フォルダ選択ダイアログ → `probe()` による検証 → 進行中操作があれば確認ダイアログ → 承認されたら旧セッション解放 → 新セッションで `MainWindow` を差し替える。
  - **新規ストレージセットアップウィザード...**：進行中操作の確認 → 承認されたら旧セッション解放 → `SetupWizard` を `context=None` から起動（アカウント登録・フォルダ選択を含む既存のウィザードフローをそのまま利用）→ 完了後に新セッションで `MainWindow` を差し替える。ウィザードでキャンセルされた場合は旧セッション・旧ウィンドウを維持する（＝キャンセル時に「ストレージ無し」状態へ落とさない）。
- ステータスバーに現在のストレージルートのパスを表示するラベルを追加する（既存の暗号化状態・容量レベルラベルと並べる）。
